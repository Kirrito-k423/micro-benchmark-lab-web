# A5 FullMesh / URMA 通信测量状态

2026-10-09：独立两 PE GM→GM PUT/GET 基准已实现，并在 A5 / CANN 9.1.0 编译通过。两次冒烟任务均因发现其他 NPU 进程，在启动测试 rank 前退出。**当前通信计时样本为 0，设备正确性未验证。** 机柜、板号和路径映射也尚未确认，因此没有柜内或跨柜带宽结论。借用资源的临时预留已释放。

[网站入口](https://kirrito-k423.github.io/micro-benchmark-lab-web/?lab=network) 展示待测矩阵与证据状态；既有 DataCopy / SIMD 数据未变化。机器占用是当时快照，不是实时监控。

[独立基准代码](https://github.com/Kirrito-k423/ascend-kernel-lab/tree/codex/a5-network-baseline/examples/a5_network) 包含 CMake、NPU kernel、双端完整 oracle、随机顺序 plan、单机/双节点 runner 和双端结果验收。先验证同主机两卡，再确认柜内 X/Y 轴设备对，最后使用不同机柜的设备对测跨柜 URMA。FullMesh 是拓扑，URMA 是接口；不能把二者当成互斥实现。

MTE 正式计划 84 个配置，URMA 148 个配置：32B～16MiB 20 档消息、PUT/GET、MTE 1～64 AIV、URMA 一个提交 AIV 的 1/2/4/8 QP 与 1/8/32/128 batch。消息×batch 超出 128MiB ring 的组合不生成。计划数量不是已测数量。

计时取发起方 ACL Event 的完整 kernel 区间，包含完成等待；Host 准备、TCP 协调、下载与验证在区间之外。每次完整校验两端源、目标及前后保护区。双节点分别回传原始结果，按 plan、binary、源文件及原始样本哈希绑定；缺少一端或 oracle 失败则拒收。原始设备/地址日志保留在私有归档，公开文件仅含脱敏参数、样本和哈希。

本阶段只测一对设备，尚不覆盖全柜 FullMesh bisection、多节点 all-to-all 或多流聚合能力。网络独占和平台未有证据时，不宣称无竞争硬件上限。
